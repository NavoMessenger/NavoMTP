# NavoMTP — установка Telemt MTProto Proxy в один клик (Docker, Nginx SNI и FakeTLS)

[简体中文](README.zh-CN.md) | [English](README.md) | [Русский](README.ru.md)

> Развёртывание и управление Telegram MTProto Proxy на базе [Telemt](https://github.com/telemt/telemt) на VPS с Debian или Ubuntu. NavoMTP при необходимости устанавливает Docker, направляет FakeTLS-трафик по SNI маскировочного домена с помощью Nginx `ssl_preread` и поддерживает несколько внешних портов.

NavoMTP предназначен для тех, кому нужен удобный установщик **Telegram MTProxy / MTProto Proxy** с Docker Compose, маршрутизацией Nginx по SNI, FakeTLS, поддержкой `ad_tag` и терминальным меню управления. Не требуется вручную создавать `config.toml`, Compose-файл или конфигурацию Nginx stream.

Если NavoMTP оказался полезен, поставьте репозиторию **Star** — так проект смогут найти другие пользователи Telemt.

Другие проекты, продукты и новости Navo доступны на [официальном сайте Navo](https://www.navo.im/).

## Почему NavoMTP

| Возможность | Описание |
| --- | --- |
| Установка Telemt в один клик | Проверяет наличие Docker и при необходимости устанавливает Docker Engine и Compose из официального apt-репозитория Docker |
| Интерактивное терминальное меню | Настраивает публичный адрес, несколько портов, секрет, необязательный `ad_tag` и маскировочный домен FakeTLS |

| Маршрутизация Nginx по SNI | Использует `stream` и `ssl_preread`; к Telemt передаётся только трафик с настроенным маскировочным доменом |
| Несколько портов MTProxy | Один экземпляр Telemt работает через несколько публичных TCP-портов; для каждого порта создаётся отдельная ссылка |
| Минимальная внешняя поверхность | Публикуются только порты Nginx; Telemt `9443`, Metrics и Control API остаются внутри Docker-сети |
| Сохранение IP клиента | Между Nginx и Telemt используется PROXY protocol, доверие разрешено только узлу Nginx в выделенной Docker-сети |
| Проверка и откат | Новая конфигурация проверяется до применения; при ошибке запуска или обновления восстанавливается предыдущая версия |
| Меню обслуживания | Повторная настройка, статус, журналы, обновление образов, ссылки подключения и удаление |

## Как это работает

```text
Клиент Telegram
      │ FakeTLS с настроенным SNI
      ▼
Публичные порты: 443, 12432, 22124 ...
      │
      ▼
Nginx stream + ssl_preread
      │
      ├─ SNI совпадает с маскировочным доменом ──► Telemt:9443 ──► Telegram
      └─ Неверный SNI / нет SNI / не TLS ──► отклонение
```

Nginx не перенаправляет соединения на произвольное имя, переданное клиентом, поэтому сервер не превращается в открытый TCP-прокси. Поскольку маршрутизация основана на TLS SNI, включён только режим Telemt FakeTLS; режимы Classic и Secure отключены.

## Системные требования

- Debian или Ubuntu с systemd;
- архитектура `amd64` или `arm64`;
- права root или sudo;
- доступ к репозиторию Docker, GitHub, GHCR и выбранному маскировочному сайту;
- разрешённые публичные TCP-порты в облачном файрволе или security group.

## Быстрая установка Telemt MTProxy

После загрузки проекта выполните:

```bash
chmod +x navomtp.sh
sudo bash navomtp.sh
```

Чтобы сразу открыть установку:

```bash
sudo bash navomtp.sh install
```

Терминальный мастер запросит:

1. Публичный IPv4-адрес или доменное имя сервера;
2. Один или несколько TCP-портов, например `443,12432,22124`;
3. Маскировочный домен FakeTLS, например `www.microsoft.com`;
4. Количество групп подключений (`1–100`, по умолчанию `1`);
5. Для каждой группы: уникальный 32-значный шестнадцатеричный секрет (пустое значение создаёт случайный) и необязательный `ad_tag`;
6. Общие лимиты исходящей и входящей скорости (`0–100000` Мбит/с; `0` — без ограничений).

Исходящий трафик: клиент → Telegram; входящий: Telegram → клиент. Все группы, секреты, клиенты и публичные порты совместно используют один общий лимит каждого направления. Например, `10` и `25` ограничивают суммарный трафик прокси до 10 Мбит/с на отправку и 25 Мбит/с на получение (1 Мбит/с = 1 000 000 бит/с, а не 1 МБ/с). Ограничивается средняя скорость длительной передачи; допустимы кратковременные всплески.

Текущий вход IPv4 использует единую штатную политику Telemt `[access.cidr_rate_limits]` для `0.0.0.0/0`, без отдельных пользовательских лимитов. Вход IPv6 не настроен: при его добавлении потребуется пересмотреть общий бюджет. Учитывается авторизованный трафик прокси, а не другие сервисы сервера.

По умолчанию оба направления не ограничены, в том числе в старых установках без сохранённых значений. Для изменения выполните `sudo bash navomtp.sh configure`; значение `0` снимает ограничение соответствующего направления. Команда `status` показывает оба лимита. Обновление образов сохраняет настройки. Если образ Telemt не распознаёт поля лимитов, проверка остановится до замены установки; обновите образ командой `update` и повторите настройку.

После развёртывания NavoMTP выводит ссылки `tg://proxy` и `https://t.me/proxy` для каждого внешнего порта. Ссылки содержат секрет прокси, поэтому не публикуйте их открыто.

### Несколько ad_tag и групп подключений

Выполните `sudo bash navomtp.sh configure`, увеличьте количество групп и задайте секрет и `ad_tag` каждой группы. Каждая группа получает отдельные ссылки для всех публичных портов. Экземпляр Telemt, маскировочный домен и общие лимиты скорости едины для всех групп. Два лимита задаются один раз после настройки групп. Внутренние идентификаторы создаются автоматически.

Теги записываются в штатную таблицу Telemt `[access.user_ad_tags]`, а не списком в глобальный `ad_tag`. Пустой тег отключает продвижение для группы и не наследует тег другой группы. Зарегистрируйте секрет каждой группы в `@MTProxybot`, чтобы получить соответствующий тег, и распространяйте ссылки нужной группы.

Старая установка становится группой 1 с сохранением секрета, тега и лимитов. Повторная настройка сохраняет прежние значения, новые группы получают отдельные секреты. Уменьшение количества удаляет последние группы после подтверждения; их ссылки перестают работать. Обновление образов сохраняет все группы, ошибка развёртывания восстанавливает предыдущую конфигурацию. `status` показывает группы, а `links` — ссылки для каждой пары группы и порта.

Для перехода со старых групповых лимитов выполните `configure`: значения группы 1 предлагаются как общие значения по умолчанию, а остальные групповые ограничения удаляются из новой конфигурации. Обновление скрипта или образов само по себе не меняет старую конфигурацию; `status` сообщит о необходимости повторной настройки.

## Команды управления

Запуск без аргументов открывает меню:

```bash
sudo bash navomtp.sh
```

Команды также можно выполнять напрямую:

```bash
sudo bash navomtp.sh configure   # Изменить порты, секрет, ad_tag или домен
sudo bash navomtp.sh status      # Показать состояние контейнеров Telemt и Nginx
sudo bash navomtp.sh logs        # Просматривать журналы в реальном времени
sudo bash navomtp.sh update      # Обновить образы с автоматическим откатом при ошибке
sudo bash navomtp.sh links       # Снова показать ссылки Telegram Proxy
sudo bash navomtp.sh uninstall   # Удалить NavoMTP, не удаляя Docker
```

## Создаваемые конфигурации Telemt и Nginx

По умолчанию управляемые файлы хранятся в `/opt/navomtp`:

```text
/opt/navomtp/
├── compose.yaml
├── config/telemt.toml
├── nginx/nginx.conf
├── state.env
├── links.txt
├── image-digests.txt
└── backups/
```

- `state.env` и `links.txt` доступны только root;
- `telemt.toml` доступен только root и специальной GID контейнера Telemt;
- перед изменением конфигурации создаётся резервная копия с временной меткой;
- удаление NavoMTP не удаляет Docker Engine и общие образы контейнеров.

## Сеть и безопасность

- Telemt слушает порт `9443` только внутри Docker-сети;
- Metrics `9090` и Control API `9091` не публикуются;
- соединения с неверным SNI, без SNI или без TLS быстро отклоняются;
- маскировочный домен не обязан указывать на IP прокси, но должен корректно разрешаться и обслуживать HTTPS;
- все группы используют общий маскировочный домен; публичные порты внутри каждой группы используют её секрет;
- если UFW включён, NavoMTP запросит подтверждение перед открытием портов;
- правила облачного файрвола или security group необходимо настроить вручную;
- перед использованием прокси убедитесь, что это соответствует применимому законодательству и правилам сервисов.

## Часто задаваемые вопросы

### Может ли NavoMTP автоматически установить Docker?

Да. Скрипт сначала проверяет Docker Engine и Docker Compose. Если они отсутствуют, установка выполняется из официального apt-репозитория Docker. Существующие `docker.io`, Podman или сторонние контейнерные среды не удаляются автоматически.

### Можно ли использовать несколько портов Telegram MTProxy?

Да. Укажите порты через запятую, например `443,12432,22124`. Все они направляются к одному экземпляру Telemt и используют общий секрет, но NavoMTP создаёт отдельную ссылку для каждого порта.

### Должен ли маскировочный домен указывать на VPS?

Нет. Это SNI-фронт для FakeTLS-трафика. Выберите стабильный домен, который корректно разрешается и предоставляет рабочий HTTPS-сервис.

### Почему включён только FakeTLS?

Эта схема маршрутизирует соединения по SNI из TLS ClientHello. Режимы Telemt Classic и Secure не предоставляют TLS SNI, необходимый этому строгому входу Nginx, поэтому они отключены.

### Контейнеры работают, но Telegram не подключается. Что проверить?

Проверьте облачный security group, UFW, занятость портов, `sudo bash navomtp.sh status` и `sudo bash navomtp.sh logs`. Также проверьте адрес сервера, порт и секрет в ссылке. Состояние healthy у контейнера само по себе не подтверждает сквозное подключение Telegram.

### Как настроить рекламный канал MTProxy и ad_tag?

Получите 32-значный шестнадцатеричный `ad_tag` у официального Telegram-бота `@MTProxybot`, затем запустите `configure`. Продолжайте использовать FakeTLS-ссылки, созданные NavoMTP, а не устаревшую ссылку или порт, полученные при регистрации.
